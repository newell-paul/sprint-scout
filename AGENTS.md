# SprintScout: agent instructions

Browser-only planner that times cycling segment attempts to the wind. Static Next export on GitHub Pages, no server, no accounts, no API keys. Open-Meteo and OpenStreetMap are the only external services.

## Commands

```sh
pnpm install --frozen-lockfile
pnpm --filter @scout/web dev      # http://127.0.0.1:3000
pnpm verify                       # static gates, unit, component, e2e: the definition of done
pnpm test                         # unit only (seconds)
pnpm test:e2e                     # Playwright, three projects (about a minute)
pnpm check:deploy                 # static export, smoke, size, Lighthouse
pnpm evals --dry-run              # free check that every eval can fail; pnpm evals runs them on Sonnet
```

Healthy output ends with lines like `Test Files  44 passed`, `127 passed`, `ESLint: No issues found`, `CSpell: ... Issues found: 0`. Anything else is a failure to report, not to explain away. Delegate suite runs to the `test-runner` agent, the final check to the `verifier` agent, and test comment audits to the `comment-checker` agent.

## Architecture

- `apps/web`: Next 16 static export. The planner is `app/routes`: `route-drawer.tsx` is the screen, `library.ts` is storage and validation, `example-segment.ts` seeds the first visit.
- `packages/analysis`: pure deterministic maths (wind projection, ride effect, effort matching). No I/O, 100 % coverage, property tests with a fixed seed.
- `packages/application`: Open-Meteo loaders for forecast, archive and elevation, GPX parsing, route wind, terrain and shelter.
- `packages/contracts`, `testing`, `ui`: Zod schemas, shared fixtures and msw handlers, map loader.
- `apps/worker`: a reserved boundary with no runtime.
- Data flows one way: UI, then application, then analysis. The UI never does the maths itself; dependency-cruiser enforces the boundaries.

## Rules

- Strict TypeScript, pnpm workspaces, one milestone at a time.
- Calculations stay deterministic and tested.
- No Strava data, tokens or credentials anywhere. Never read `.env`; a hook blocks it.
- Every network request follows a user action or consent, with two owner-accepted exceptions (`docs/design.md`): the map's OpenStreetMap tiles, and the example segment's forecast on a first visit, which carries only its public start coordinate. The privacy e2e tests assert it.
- Work beyond a one-line fix starts from `intent/<slug>/` (see `intent/README.md` and the `intent` skill). Architectural or behavioural changes get a dated entry in `docs/design.md`.
- Baselines under `__aria__` and `__screenshots__` are regenerated by the test runner, never hand-edited.
- Bug fixes are test-first (the `bugfix` skill). Agents merge a pull request or trigger a Pages deploy only when the owner asks and Checks are green; they never push to `main` directly or force-push (the `release` skill).
- Before reporting done: `pnpm verify` green, or say exactly what failed.

## Known mistakes

Add a line whenever the same thing happens twice.

- `next dev` rewrites `apps/web/next-env.d.ts` and `apps/web/AGENTS.md`; restore them with `git checkout --` before staging.
- `playwright test --project X spec` reads the spec as a project name; spec paths go before `--project`.
- `allowedDevOrigins` replaces the defaults; always include `localhost` and `127.0.0.1`.
- `crypto.randomUUID` is undefined over plain HTTP on a LAN address; use `newId()` from `library.ts`.
- `localeCompare` ordering differs by locale; sort with code-unit comparison and a stable tie-breaker.
- `Intl` patterns differ between Node and browser ICU, so server-rendered text hydrates wrong; format with `formatZonedTime` from `components/time.ts`.
- An emptied library is stored as `[]`; only an absent key counts as a first visit.
- `next/font/google` fetches at compile time and fails whole e2e shards when Google blips; fonts come from `apps/web/app/fonts.ts` (`next/font/local`).
- A page that reloads itself in a loop under `next dev` (e2e stuck on `data-hydrated="false"`, "[Fast Refresh] rebuilding" over and over) is a stale Turbopack cache; delete all of `apps/web/.next`, never just part of it.
- Local e2e reuses any server on :3000 and its `.next` cache; after stopping or restarting a dev server, delete `apps/web/.next` before `pnpm verify` or `pnpm test:e2e`, or the run hits that reload loop.
- A WebKit failure that never reproduces on macOS ("element is not stable", actions hanging to the timeout) needs the Linux Playwright container CI uses; `scripts/visual-baselines.sh` shows how to run it.
- An e2e step that acts before the app is ready passes locally and fails on slower CI runners; wait for the visible precondition first (the forecast placeholder before `page.clock.runFor`, hydration before acting on the page).
- `pnpm verify` lints, formats and spell-checks git-ignored folders too (`shotgun/`, scratch probes); notes and scripts left there must pass the gates, or move them out of the repo.
- A `--branch main` filter also matches a fork's pull request from its own main; a workflow that reads another run's artifacts filters on the run's head repository, not the branch name.
