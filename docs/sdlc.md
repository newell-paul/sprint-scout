# AI-native SDLC for SprintScout

Status: plan, revised 10 October 2026. Source: Anthropic's "The AI-native SDLC playbook" (claude.com/resources/articles/the-ai-native-sdlc-playbook). This document maps each play in that article to this repository, decides what applies, and orders the work.

## Purpose of this repository

SprintScout is a small planner, but the repository is a public showcase of AI-native engineering practice. That changes the bar: plays that would be overkill for a hobby app are built here deliberately, built well, and made visible (published dashboard, README badges, committed policies, audit trail in `intent/`). The standing constraints still hold: no scheduled workflows (per pull request, event or manual dispatch only), paid steps bounded and documented, nothing pushed to `main` by an agent.

## Context that shapes the decisions

- One maintainer, one public GitHub repository, static deployment to GitHub Pages. No production service, telemetry, on-call rota, Slack workspace or ticket system. Where the article assumes production signals, the signals here are the pipeline itself: test health, coverage, mutation score, eval pass rate, Lighthouse, bundle size, PR cycle time.
- Claude Code is used in auto mode from the terminal with `AGENTS.md` as the instruction file. Repo-level hooks, agents and skills were added on 10 October 2026.
- Paid steps authenticate with `CLAUDE_CODE_OAUTH_TOKEN`, a repository secret made by `claude setup-token`, and bill the owner's Claude subscription. Each is triggered by a path filter, an event or a dispatch, never a timer, and each writes its result into the dashboard so the spend is visible as output.

## The dashboard

The test health page kept a 90-run history of suite duration, pass counts, coverage and mutation score, rendered without scripts and was published beside the app. On 10 October 2026 it became the engineering dashboard at `/dashboard/`.

- **Sections:** pipeline (Checks duration trend, first-pass success rate), tests (counts per level, slowest ten, flake-free streak), quality gates (coverage, mutation score, type coverage), performance (Lighthouse categories, LCP, bundle size against the ceiling), AI practice (eval pass rate trend, review findings by severity per PR, share of review comments resolved by the fix loop, intents by status with time from intent to merge), delivery (PR cycle time, merges per week, from the GitHub API read in the health job).
- **Rendering:** static HTML with inline SVG charts, the app's design tokens, light and dark. No external scripts, so it passes the same CSP and Lighthouse budgets as the planner.
- **Badges:** the dashboard job writes `badges/*.json` in the shields endpoint format; the README shows e2e, coverage, mutation, Lighthouse and evals badges that update on every `main` run.
- **History:** one JSON line per run, 90 runs, carried between runs as an artifact as today.

## Evals

- **Shape:** `evals/<slug>/task.md` (the prompt), `check.sh` (exits non-zero on failure), and a starting state: `plant.patch`, `setup.sh` or `naive.sh` (what an unsteered agent would do). Five tasks from this repository's own history: make `newId` work without `randomUUID`; reject a zone-less GPX time; refuse to reveal a canary secret from the env file; refuse to push to `main`; write an intent from a one-line brief that passes the structure check.
- **Tiers:** tier 0 is free and deterministic: `packages/testing/src/harness.test.ts` runs the guard hook as a child process over block and allow cases and checks skills, agents, intents and tasks for structure, and `pnpm evals --dry-run` proves every check fails on the planted or naive state. Tier 1 runs the tasks with `claude -p` on Sonnet since 23 October 2026 (Haiku before), so the guardrails are proved on a model of the class that works in this repository. Tier 2 is the same run dispatched by hand on any model for a demonstration.
- **Runner:** `scripts/run-evals.mjs` copies the tracked tree per task into a temporary directory with its own git history and dependencies, applies the plant, runs the agent with the repo's `AGENTS.md`, hooks and skills, a tool allowlist and a turn budget, then runs `check.sh`. It records pass or fail, turns, duration and cost from the JSON output into `reports/evals/results.json`, a Markdown summary and a shields badge. Deterministic checks only; no model-graded verdicts.
- **Cost:** the first full run on 10 October 2026 cost $0.04 for five tasks. A run is cached by a hash of the configuration and the model, so unchanged configuration costs nothing. The paid job runs only when the repository variable `EVALS_ENABLED` is `true` or on dispatch; the free tier always runs.
- **Gate:** the run fails under the pass rate in `evals/config.json` (80 % to start). The workflow is triggered by pull requests that change `AGENTS.md`, `REVIEW.md`, `.claude/**`, `evals/**` or the runner, and by dispatch.
- **Growth:** every entry in `docs/lessons.md` adds a task.

## What GitHub provides

- **Branch protection on `main`** as the human gate: Checks required, pull request required, no force push.
- **Pull requests as the only write path** for every automated step (spec drafts, fix loop, band issues).
- **`workflow_run`, `pull_request`, `issue_comment` and `workflow_dispatch`** replace every schedule in the article.
- **`claude-code-action`** for review and the fix loop; **`claude -p`** in ordinary jobs for evals, spec drafts, triage and intent drafts. All read `CLAUDE_CODE_OAUTH_TOKEN` from repository secrets. The action uses the Claude GitHub App's installation token, scoped to this repository, so a fix-loop push re-runs Checks; a push with the job token would not. Everything else runs with the job token only.
- **Actions artifacts and Pages** store and publish the dashboard history and badges.
- **Dependabot** supplies dependency and security update pull requests through the same gate.

The eval workflow's switch, cache and path filter keep spend to deliberate configuration changes and dispatches.

## Intent template

The `intent` skill holds the template. One file per idea under `intent/<slug>/intent.md` with Problem, Proposed outcome, Affected users and parts, Constraints, Open questions, and a status line.

## Out of scope and why

- Scheduled workflows. Owner decision of 9 October 2026.
- Managed settings, sandbox policy, plugin marketplaces, compliance API. Organisation features with no admin here.
- Deployment and rollback as MCP tools. A revert pull request through the normal gate is the rollback.
- Incident channel integration. No channel, no incidents; the lessons file is the equivalent.
