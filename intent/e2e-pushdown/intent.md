# Push e2e checks down to the lowest level that proves them

Status: done
Opened: 26 October 2026 by Paul Newell

## Problem

The Playwright suite has about 152 desktop scenarios against 63 component tests. An audit on 26 October 2026 read every e2e test against the component and unit tests: 118 need the whole app, but 8 repeat an existing component test and 32 assert one component's state (an error message, a disabled control, a formatting rule) that a component test proves faster and with less timing risk. Four of those are clock-driven forecast fault tests, the kind AGENTS.md records failing on slower CI runners.

## Proposed outcome

The 8 duplicates are gone, and each of the 32 is replaced by a component test (31) or a unit test (1) asserting the same behaviour before its e2e test is removed. The e2e suite keeps every journey that needs the page: drawing and the editor, reload and storage, other tabs, the real map, network and consent, page-level keyboard, mobile layout, and the WebKit `@a11y` and `@keyboard` runs.

## Affected users and parts

`e2e/*.spec.ts` and page objects; `apps/web/app/routes/*.browser.test.tsx` (wind preview, efforts panel, terrain panel, rider settings, opportunity board, clear data); `apps/web/app/components/ride-cockpit.browser.test.tsx`; `apps/web/app/components/conditions.test.ts`; `docs/test-strategy.md`. No product code changes.

## Constraints

No behaviour loses its only test. A moved test must be able to fail. ARIA baselines are generated by the runner, never hand-edited. Calculations stay deterministic.

## Open questions

None; the audit verdicts are listed in spec.md.
