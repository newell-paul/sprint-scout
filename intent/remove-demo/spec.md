# Spec: Remove the synthetic demo

## Behaviour

- `/` is unchanged: every control, state, keyboard path and network request stays as it is.
- `/demo` and `/api/planner` return the app's normal not-found page under `next dev`. They were never in the Pages export, so the published site does not change.
- `/health` still answers 200 with `{ "status": "ok" }`; the `mode: "demo"` field goes, since nothing reads it.

## What goes

### Web

- `apps/web/app/demo/`, `apps/web/app/api/planner/`.
- `components/planner.tsx`, `route-map.tsx`, `hour-chart.tsx`, `ride-effect.tsx`. The rest of `components/` stays (`logo`, `time`, `speed`, `conditions`, `time-chart`, `ride-cockpit`, `weather-icon`).
- In `globals.css`, the demo-only rules:
  - `.planner` and its descendants, from the topbar through the skeleton loader, with the matching lines in the media queries;
  - `aside[aria-label="Demo mode"]`, `.map-shell`, `.ride-effect*`, `.demo-logo`;
  - the `.planner` / `.ride-effect-value` entries in the mono selector list.
- The element rules between those blocks stay (`label`, `select`, `table`, `caption`, `td`/`th`, `input[type=range]`, `hr`, `summary`), as do `.table-scroll`, `.sr-only`, `.skip-link` and `.maplibregl-*`.
- Two classes are shared with `/`. `.primary` is used by the board and the drawer, so it moves into the planner's own rules. An unscoped `.empty` also matches `segment-slot … empty`; it is removed only if a `.segment-slot` rule already gives the same result, and the visual and ARIA checks prove it.
- `next.config.ts` stops transpiling `@scout/providers`; `@scout/application` stays (the planner imports its subpaths).

### Packages

- `packages/ui`: `DemoBanner`, `route-map`, `hour-chart`, `map.css` and `configureMapLibre`, which had no other users. `maplibre.ts` stays. The `echarts`, `react`, `react-dom` and `@scout/contracts` dependencies go; only `maplibre-gl` stays.
- `packages/application`: the root entry (`index.ts`) and everything only it reaches:
  - `policy.ts`, `wind.ts`, `forecast.ts`, `time.ts`, `planner.ts`, `weather-demo.ts`, `departure.ts`, `wind.benchmark.ts`, and their tests;
  - the `@scout/providers`, `@js-temporal/polyfill` and `@turf/distance` dependencies.
  - `route-wind`, `terrain`, `shelter`, `gpx` and `archive-wind` stay.
- `packages/providers`: the whole package, including `weather.smoke.ts` behind `test:weather:live`. The live Open-Meteo drift check stays; it lives in `packages/testing` and uses the `openMeteo*` schemas.
- `packages/contracts`: the exports with no surviving caller go:
  - `contractVersion`, `effort`, `errorCode`, `units`, `Segment`;
  - the forecast and planner schemas and types, `defaultPlannerRequest`, `rideEffect`, `displayZone`, `segmentSummary`, `demoConditions`, `weatherHour`, `utcInstant`.
  - `coordinate`, `segment`, `provenance`, `sourcePolicy`, `sourceKind`, `attribution`, `Provenance` and the `openMeteo*` schemas stay. `segment` keeps its provenance check, because `packages/analysis` validates input with it.
- `packages/analysis`: the hourly ranking block goes: `weatherIndex`, `defaultIndex`, `evaluateHour`, `rankOpportunities`, `validateOptions` and their types. With it go `ranking.golden.test.ts` and `fixtures/evaluate-hour.golden.json`, the `weatherIndex` half of `wind.property.test.ts`, and the cases in `wind.test.ts`, `analysis-errors.test.ts` and `boundaries.test.ts` that call removed functions. `prepareGeometry`, `projectWind`, ride effect, terrain effect and effort matching stay, with their tests.
- `packages/database` and `apps/api`: deleted.

### Repository

- `compose.yaml`; the "Database (testcontainers)" job in `ci.yml`; the vitest `integration` project and its coverage excludes.
- Root scripts: `test:integration`, `db:migrate`, `db:seed`, `benchmark:wind`, `test:weather:live`; `@scout/api` is dropped from `dev` and `build`.
- Configs:
  - `knip.json` loses the `apps/api` workspace;
  - the dependency-cruiser rule and comment that name `providers` and `database` are rewritten for the packages that remain;
  - `stryker.config.json` loses the `weather-demo.ts` exclusion;
  - `playwright.static.config.ts` loses its `demo.spec.ts` ignore;
  - `cspell.json` loses words that no longer appear.
- The lockfile is regenerated by `pnpm install`.

## Data and privacy

Nothing new leaves the browser. Removing code only takes requests away, and the privacy e2e tests run unchanged.

The env example documents `DATABASE_URL`, which the database package read. Agents may not open that file, so the owner removes that line by hand; the plan lists it as an owner step. The env-refusal eval keeps its canary (`DEMO_SECRET`), which is a test value and not part of the demo.

## Calculations

No change on `/`. Every function the planner calls stays byte-for-byte the same; only functions with no surviving caller go. `packages/analysis` keeps 100 % coverage. Its remaining property tests (`projectWind`, ride effect, effort matching) keep their fixed seeds.

## Tests

- **Removed:**
  - `e2e/demo.spec.ts`, `e2e/pages/demo.ts` and their uses in `e2e/fixtures.ts` and `e2e/pages/index.ts`;
  - the "demo planner chart" visual test and `demo-hour-chart.png`;
  - unit tests of removed code;
  - the integration suite.
- **Kept:** `forecast.spec.ts` keeps checking that `/` has no demo link; the locator stays on the planner page object.
- **Visual:** the three planner visual tests stay (dial and compass at a tailwind hour, calm dial, timeline bands). They already cover `/`, so no replacement for the demo chart is added.
- **ARIA snapshots:** none of the planner's change; the CSS removal must leave every `__aria__` file as it is.
- **Dashboard bands:** the cut lowers the unit count by about 80 and the e2e count by about 26. Both are 3σ breaches with `minSigma: 1`, which would fail the dashboard job and the Checks run on main.
  - `bands.yaml` gets an optional per-band `since` (an ISO timestamp): runs before it drop out of the baseline. The band then reads "baseline needs 5 runs" until five new runs exist.
  - `since` is set on `e2e-count`, `unit-count`, `line-coverage`, `branch-coverage` and `mutation`, in the last commit before merge.
  - `bands.test.ts` covers the new field: a run before `since` is ignored, and a band with fewer than `minRuns` runs after it stays at level 0.
- **Dashboard text:** the "database" job name in `dashboard.ts` goes.

## Docs

- `AGENTS.md`: the Architecture section loses `providers`, `database` and `apps/api`, and the commands lose the removed scripts. The `/demo` mention in the known-mistakes line goes.
- `README.md`, `docs/implementation-plan.md`, `docs/test-strategy.md`, `docs/sdlc.md`, `docs/validation.md`, `docs/integration-decisions.md` and `docs/lessons.md`: present-tense descriptions of the demo, API or database are corrected. Dated history stays as written.
- `docs/design.md`: a new entry, "Synthetic demo removed — <date>", gives the reason, what went, and the band baseline restart.
- `intent/aero-stealth/plan.md`: the follow-up points to this intent.

## Open questions resolved

1. Dead code: everything listed under Packages. The provenance policy, the hourly ranking and its golden fixtures served only the demo.
2. The env example: `DATABASE_URL` only, and the owner removes it. The env-refusal canary is unrelated and stays.
3. Bands: unit and e2e counts would breach, so the bands get a `since` restart. No downstream job in `ci.yml` needs the database job.
4. Configs: knip, dependency-cruiser, vitest, stryker, the static Playwright config, `next.config.ts`, `cspell.json` and the root scripts all change. `pnpm-workspace.yaml` and `tsconfig.json` use globs and do not.
5. Visual tests: the three planner tests are enough; no replacement.
