# Spec: remove terrain and Open-Meteo elevation

## Behaviour

- The terrain panel is gone from the planner: no load button, no consent or automatic-reload boxes, no profile, no samples table.
- The ride cockpit always shows the flat-road label, "Modelled at constant effort · Flat road · Terrain not modelled", and "Still air" for the baseline. The "terrain not loaded" message and the "same terrain" wording go.
- The opportunity board no longer labels a segment's model, because there's only one.
- Wind preview notes describe the flat-road model only.
- The clear-data text no longer mentions terrain profiles.

## Data and privacy

- No request to `api.open-meteo.com/v1/elevation`, ever.
- The forecast, archive and map tile requests are unchanged.
- `readLibrary` ignores `terrain`, `terrainMode` and `terrainAuto` whatever their value: valid, invalid or a wrong type. It returns the segment without them, so the next save writes a clean library. A library that only failed because of a malformed `terrainAuto` now loads.

## Calculations

- `estimateRouteRideEffect` loses its terrain argument and always uses `ride-effect-v1`.
- The terrain physics (`terrain-effect-v1`) and its property tests are removed.
- Flat-road numbers are unchanged; the existing flat-road tests and golden fixtures prove it.

## Tests

- Removed:
  - terrain unit, property, component and e2e tests;
  - the terrain ARIA baselines;
  - the elevation fixture and handler.
- Updated:
  - library tests: legacy terrain fields are dropped, and a malformed `terrainAuto` no longer rejects the library;
  - Open-Meteo call counts, which no longer have an `elevation` key;
  - cockpit, wind preview and board tests and their baselines, regenerated by the runners.
- Privacy e2e: it asserts there's no elevation request after the planner loads and the example forecast arrives.

## Docs

- `docs/design.md` entry: "Terrain removed — 1 November 2026". It supersedes the terrain sections, which stay as history.
- `AGENTS.md`, `README.md`, `docs/test-strategy.md` and the other current-state docs are updated.
